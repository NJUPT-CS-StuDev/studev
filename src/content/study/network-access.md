很多“打不开”的问题，并不等于“网站坏了”。先把问题拆成几层，才能知道下一步该验证什么。

## 先问：是哪一层出了问题？

可以按照从近到远的顺序排查：

1. **设备与浏览器**：换一个浏览器、网络或设备，确认是不是本地状态。
2. **域名解析**：域名是否解析到了预期的地址，证书是否匹配。
3. **网络路径**：请求是否能抵达服务，是否被代理、防火墙或区域策略截断。
4. **应用本身**：服务是否启动，路由、资源和权限是否正确。

每一步都应该留下一个小结论，而不是一次性尝试十个工具。

## 一个好的排查记录

把“我试过了”换成可以被别人复现的句子：**时间、环境、动作、结果、下一步**。例如：

> Windows 11 / Edge / 校园网；DNS 能解析，HTTPS 握手成功，但静态资源返回 404；下一步检查构建产物中的 base 路径。

这类记录本身就是学习产物。它让下一次遇到相似问题时，不必从零开始。

## 留下什么

不是所有日志都应该公开。公开内容保留方法、判断和脱敏后的结果；令牌、个人信息、内部地址和未确认的结论，留在私有环境。
